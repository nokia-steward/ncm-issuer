# What's changed

ncm-issuer 1.3.1 fixes enrollment against an NCM that serves its REST API under a base path such as `/rest`, sends requests to the backup NCM API with its own host name and fixes a Go standard library vulnerability reachable from the controller.

### Security fixes

- Upgraded **Go** to `1.26.11` for the binary and Docker image. This clears GO-2026-6859 (CVE-2026-97054) in `net/http`, which is reachable from the controller

- **Updated `golang.org/x/net` to `v0.62.0`** for GO-2026-6860 (CVE-2026-78661) and GO-2026-6866 (CVE-2026-97045) in `golang.org/x/net/html`. Image scanners report them, but the controller does not call the affected code

### Bug fixes and improvements

- **`provisioner.mainAPI` and `provisioner.backupAPI` may now include the NCM REST base path**, for example `http://ncm.example:8084/rest`. ncm-issuer used to drop the `mainAPI` path when it listed CAs and sent CSRs, so it called `/v1/cas` and `/v1/requests` and NCM answered 404 while the issuer still reported `Ready=True`. With a path in `backupAPI`, requests that follow NCM hrefs (CSR status, certificate download, renewal and the CA chain) went to `/rest/rest/v1/...`. The base path is now added to `/v1/cas` and `/v1/requests` only. Href paths are sent as NCM returned them. A reverse proxy added to map `/v1/` to the base path is no longer needed
- **Requests sent to the backup NCM API now carry the `backupAPI` host in the `Host` header.** They used to carry the `mainAPI` host, so a backup NCM behind a proxy or load balancer that routes by host name could reject them or pass them to the wrong service
- Updated `go.mod` dependencies: **cert-manager** to `1.21.3`, **Kubernetes API** to `0.37.2`
